## 🎯 Make 命令分析

### RPC 服务 Makefile

**位置**: `/opt/code/newbee/unified-io/rpc/Makefile`

#### 关键命令

| 命令 | 作用 | 是否覆盖文件 |
|------|------|-------------|
| `make gen-ent` | 生成Ent代码 | ✅ 会覆盖 `ent/` 目录下生成的文件 |
| `make gen-rpc` | 从proto生成RPC代码 | ✅ 会覆盖部分文件 |
| `make gen-rpc-ent-logic` | 从Ent生成logic代码 | ⚠️ 有`--overwrite`参数 |

#### gen-rpc 命令详情

```makefile
gen-rpc: # Generate RPC files from proto | 生成 RPC 的代码
	goctls rpc protoc ./$(SERVICE_STYLE).proto --go_out=./types --go-grpc_out=./types --zrpc_out=. --style=$(PROJECT_STYLE)
	sed -i 's/,omitempty//g' ./types/$(SERVICE_LOWER)/*.pb.go
```

**覆盖文件**:
- `types/io/*.pb.go` - ✅ **完全覆盖** (protobuf生成文件)
- `internal/server/io_server.go` - ✅ **完全覆盖** (带有 `DO NOT EDIT` 标记)
- `ioclient/io.go` - ✅ **完全覆盖** (RPC客户端)
- `io.go` - ✅ **覆盖** (主文件)
- `etc/io.yaml` - ⚠️ **可能覆盖** (配置文件)

**不覆盖文件**:
- ❌ `internal/logic/**/*_logic.go` - **不覆盖** (业务逻辑)
- ❌ `internal/svc/service_context.go` - **不覆盖** (服务上下文)
- ❌ `internal/config/config.go` - **不覆盖** (配置定义)

#### gen-rpc-ent-logic 命令详情

```makefile
gen-rpc-ent-logic: # Generate logic code from Ent
	goctls rpc ent --schema=./ent/schema --style=$(PROJECT_STYLE) --multiple=false \
	  --service_name=$(SERVICE) --output=./ --model=$(model) --group=$(group) \
	  --proto_out=./desc/$(shell echo $(model) | tr A-Z a-z).proto \
	  --i18n=$(PROJECT_I18N) --overwrite=true
```

**⚠️ 关键参数**: `--overwrite=true`

**覆盖范围**:
- `desc/*.proto` - ✅ **完全覆盖** (proto定义)
- `internal/logic/$(group)/*_logic.go` - ⚠️ **会覆盖** (当overwrite=true时)

## 🛡️ 保护策略建议

### 策略1: 版本控制保护

```bash
# 在执行任何make命令前，提交当前更改
git add .
git commit -m "保存当前工作 - 执行make命令前"

# 执行make命令
make gen-rpc

# 检查变更
git diff

# 如果有意外覆盖，可以回滚
git checkout -- <被错误覆盖的文件>
```

### 策略2: 备份关键文件

```bash
# 创建备份脚本
cat > /tmp/backup_unified_io.sh << 'EOF'
#!/bin/bash
BACKUP_DIR="/tmp/unified-io-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p $BACKUP_DIR

# 备份RPC关键文件
cp -r /opt/code/newbee/unified-io/rpc/internal/svc $BACKUP_DIR/rpc-svc
cp -r /opt/code/newbee/unified-io/rpc/internal/logic $BACKUP_DIR/rpc-logic
cp -r /opt/code/newbee/unified-io/rpc/internal/config $BACKUP_DIR/rpc-config

# 备份API关键文件
cp -r /opt/code/newbee/unified-io/api/internal/svc $BACKUP_DIR/api-svc
cp -r /opt/code/newbee/unified-io/api/internal/logic $BACKUP_DIR/api-logic
cp -r /opt/code/newbee/unified-io/api/internal/config $BACKUP_DIR/api-config

echo "备份完成: $BACKUP_DIR"
EOF

chmod +x /tmp/backup_unified_io.sh
```

### 策略3: 修改Makefile参数

**修改RPC Makefile中的overwrite参数**:

```makefile
# 原始 (危险)
gen-rpc-ent-logic:
	goctls rpc ent ... --overwrite=true

# 修改为 (安全)
gen-rpc-ent-logic:
	goctls rpc ent ... --overwrite=false
```

**优点**: 
- ✅ 不会覆盖已存在的logic文件
- ✅ 只生成新的proto文件

**缺点**:
- ⚠️ 如果需要更新logic，需要手动删除后重新生成

### 策略4: 使用git stash

```bash
# 暂存当前修改
git stash push -m "临时保存 - make gen-rpc前"

# 执行make命令
make gen-rpc

# 恢复修改
git stash pop

# 解决冲突（如果有）
```

## 🔄 安全工作流程

### 新增模型时

```bash
# 1. 备份现有代码
git add .
git commit -m "新增模型前备份"

# 2. 修改schema
vim rpc/ent/schema/new_model.go

# 3. 生成Ent代码
cd rpc && make gen-ent

# 4. 生成proto和logic (使用overwrite=false)
# 修改Makefile: --overwrite=false
make gen-rpc-ent-logic model=NewModel group=new_model

# 5. 生成RPC代码
make gen-rpc

# 6. 检查变更
git diff

# 7. 手动合并logic代码（如果需要）
```

### 修改现有模型时

```bash
# 1. 备份
git add .
git commit -m "修改模型前备份"

# 2. 修改schema
vim rpc/ent/schema/existing_model.go

# 3. 重新生成Ent
cd rpc && make gen-ent

# 4. ⚠️ 不要运行 gen-rpc-ent-logic (会覆盖logic)
# 5. 手动更新logic代码以适配schema变更

# 6. 如果proto需要更新，手动修改proto
vim desc/existing_model.proto

# 7. 重新生成RPC
make gen-rpc

# 8. 修复编译错误
go build -v .
```

### 修改API定义时

```bash
# 1. 备份
git add .
git commit -m "修改API前备份"

# 2. 修改API定义
vim api/desc/all.api

# 3. 生成API代码
cd api && make gen-api

# 4. 检查routes.go变更
git diff internal/handler/routes.go

# 5. handler文件首次生成后可以修改
# 6. logic文件不会被覆盖，安全
```

## 🎯 最佳实践建议

1. **修改Makefile**
   ```makefile

   gen-rpc-ent-logic: --overwrite=false
   ```

2. **使用版本控制**
   - 每次make前commit

   - ✅ `internal/config/` - 配置定义
